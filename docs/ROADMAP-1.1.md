## 3. 역할 분담 원칙 (준희 ↔ 태희)

준희가 제시한 방식 — **"준희가 구조를 짜면 태희가 기술 구현"** — 을 기존 창구 규칙과 합치면 이렇게 된다.

| 영역 | 준희 | 태희 |
|---|---|---|
| **제품 구조 결정** (게시판 층위·권한 단계·라운지 명칭·콘텐츠 정책) | 🟢 **결정권자**. 구조안을 문서로 확정 | 구현 가능성·비용 피드백 |
| **firestore.rules · src/types/** | 제안만 | 🟢 **창구 일원화**(기존 규칙 유지). 변경·배포 담당 |
| **게시판/쪽지/라운지/신고·차단/테마 화면** | 🟢 준희 축 | — |
| **인증/시간표/친구/i18n·온보딩** | — | 🟢 태희 축 |
| **데이터 수집** | 明治 · 早稲田 · 法政 | 上智 8학부 · 他校 출처 조사 |
| **Firestore 적재** | 🟢 준희 (서비스계정 키가 준희 PC에만) | — |
| **콘텐츠 운영** | 🟢 준희 (소재 결정·최종 게시) | — |
| **스토어 제출·배포** | 🟢 준희 (정지선) | — |

**충돌 방지**: 학교 분기(§4-C1)는 `src/types/`·`schools.ts`를 건드리므로 **태희 창구**. 준희는 "어떤 UX여야 하는가"를 문서로 넘긴다.
