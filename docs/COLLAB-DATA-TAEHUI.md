iOS 1.0은 심사 중(2026-10-24 제출)이고, 심사와 무관하게 **데이터는 계속 늘려야 한다.**

## 4. 태희 측에 요청하는 것 (우선순위 순)

1. **G2 검색 gram 개선** — 가장 체감이 큼. 제안: 질의의 모든 2-gram 중 **가장 드문 것**을 고르거나, 2개 gram으로 두 번 질의해 교집합. `CANDIDATE_LIMIT` 300→상향. 바꾸면 메이지 전 학부에서 "英語"·"演習" 검색이 뜨는지 확인.
2. **G3 1글자** — 앱·적재 양쪽 `makeBigrams`를 **같은 PR에서** 바꾸거나, 앱에서 1글자면 "2글자 이상 입력" 안내.
3. **G4 타입 확장 여부 결정** — `day/period` optional + `Day`에 `日` 추가를 할지, 1.0에서는 보류할지. 보류면 매뉴얼 §11-4에 "보류" 기록.
4. **R1 便覧 PDF** — 理工·情コミ 재학생 지인을 통해 2026년도 便覧 PDF 입수 가능하면 `docs/binran/`(gitignore 대상)에.
5. **R4 다학교 통합 설계 착수 시점** — 他校 JSON이 4건 이상 쌓인 지금이 적기인지 의견.
6. **분반 표시(UI)** — 共通外国語는 같은 이름·교수·시간대의 **분반**(수업번호만 다름)이 검색 결과에 여러 줄로 나와 중복처럼 보인다(예: `English Communication ⅠＣ 土3` ×2). 데이터는 정상이므로 결과 카드에 수업번호(`courseNumber`) 또는 분반 표시를 붙이거나 같은 슬롯을 묶는 UI 검토(검색 화면은 태희 축).

## 5. 양측 Claude가 지킬 공통 규칙

- **DATA-MANUAL.md 절차 외의 방법을 쓰지 않는다.** 새 함정을 만나면 매뉴얼 §9에 **추가**하고 PR에 넣는다(지식을 문서에 쌓는다).
- `zone.id`·파일명·`AllocCourse` 형식·`Course` 타입은 **계약**이다. 한쪽이 바꾸면 반드시 공문(이 문서)에 적고 상대 축에 알린다.
- `makeBigrams`는 앱과 적재 스크립트에 **이중 관리**된다. 한쪽만 바꾸면 검색이 조용히 0건이 된다.
- 브랜치: `master` 최신화 → `data/…`(데이터) / `feat/…`(기능) → PR. 머지는 준희. 서로의 축 파일을 건드릴 땐 PR 본문에 `@상대` 표시.
- 심사 중엔 production OTA 금지. 데이터 JSON·docs PR은 언제든 머지 가능(앱 번들에 안 들어가면 배포 영향 없음).

## 7. 태희 회신 (2026-10-25)

### G2 검색 누락 — ✅ 처리 (PR: `fix/course-search-truncation`)

**원인이 가정과 달랐습니다. "0건"이 아니라 "잘림"이었습니다.**
측정 결과(2026春 「英語」):

| 학부 | 보이던 수 | 실제 해당 수 | 누락 |
|---|---|---|---|
| 理工 | 169 | 235 | **66 (28%)** |
| 商 | 197 | 221 | 24 |
| 政経 | 148 | 153 | 5 |
| 나머지 8개 | — | — | 0 |

`CANDIDATE_LIMIT`(300)이 **연도·학기 필터 전에** 걸려서, 상한이 다른 학기 과목으로 채워진 뒤 春 필터에 깎였습니다.
즉 gram 선택 문제가 아니라 **필터 순서** 문제였습니다.

**수정**: 연도·학기를 **서버 측 등가 필터**로 올렸습니다. 상한은 "그 학부·그 학기에 실재하는 해당 과목 수"에만 적용됩니다.

> ⚠️ **복합 인덱스 추가 배포는 불필요합니다.** `array-contains` + 등가 2건이 기존 인덱스로 통하는 것을 실데이터로 확인했습니다(理工 235건 반환).

`CANDIDATE_LIMIT`은 300 → **500**. 관측 최대가 「演習」 政経 426건이라 여유를 뒀습니다.
검증: 11개 학부 × 「英語」「演習」「経営」 전부 **실제 해당 수와 완전 일치**.

### G3 1글자 — ✅ 안내로 처리

재현됨(「法」→ 0건). 적재가 2-gram뿐이라 1글자는 구조적으로 0건입니다.
**적재 재실행(19,672건) 없이** 앱에서 「2文字以上で検索してください」를 띄우는 쪽을 택했습니다(ja/ko).
1-gram 적재는 인덱스·문서 크기가 커지는 데 비해 1글자 검색의 효용이 낮다고 봅니다. 필요하면 다시 논의하죠.

### G4 day/period nullable — 🟡 1.1 (1.0 보류)

`Course`·`Day` 변경은 **크롤러 출력 규격**(AGENTS 규칙)이라 타입·`load-firestore.mjs`·시간표 UI 3곳을 동시에 봐야 합니다.
심사 중 타입을 건드리는 건 위험하므로 **1.1 상위**로. 준희 안건 3번과 같은 건이라 거기서 같이 정하죠.

### R1 便覧 PDF — 🟡 시도해보겠습니다

理工·情コミ 재학생 지인에게 2026년도 便覧 PDF를 받을 수 있는지 알아보겠습니다. 확보되면 `docs/binran/`에 넣겠습니다.

### R4 다학교 통합 — 🟡 1.1 이후 권장

他校 JSON이 4건이지만 **검증 완료는 3건**이고, `facultyMasters.ts`가 `meiji.ac.jp` 고정입니다.
지금 통합하면 (학교×학부×연도×학과) 4중 분기가 되는데, 他校는 아직 강의 데이터가 0건이라
**졸업요건만 되고 검색은 안 되는 반쪽 상태**가 됩니다. 他校 강의 크롤(G6)과 함께 묶는 쪽이 사용자 체감이 큽니다.
→ 1.1에서 "他校 1개교(早稲田) 완전 지원"을 먼저 해보고 패턴을 굳히는 안을 제안합니다.

### 분반 표시(§4-6) — 🟡 1.1

같은 이름·교수·시간대가 여러 줄 나오는 건은 결과 카드에 수업번호를 붙이는 게 가장 싸고 정확합니다.
다만 `Course`에 `courseNumber`가 들어 있는지 확인이 먼저입니다. 1.1 로드맵에 올리죠.

### 9-2. 태희 측 시작 방법 (태희 Claude에게 그대로 붙여넣기)

```
docs/DATA-MANUAL.md 와 docs/COLLAB-DATA-TAEHUI.md §9 를 읽고, §9-1 담당표의 「태희」 행만 진행해.
대상: 上智大学 <학부> 2026 (또는 他校 출처 조사). 매뉴얼 절차대로만, 수치는 출처에서만, 애매하면 "미검증".
끝나면 MASTERS-INDEX의 해당 행만 갱신하고 data/<school>-<faculty>-2026 브랜치로 PR.
```
- 최초 1회: `git pull` → `cd scripts/binran && npm install` (PDF 추출 도구)
- **JSON까지만** 만든다. 他校는 앱 미연동(1.1 학교 분기 설계 전)이라 `facultyMasters.ts`·Firestore는 건드리지 않는다
- 上智는 **학부마다 PDF 조판이 다르다**(공통 파서로 9학부 돌리면 神学部만 합계가 맞았음) → 학부별로 `rawxy.mjs`로 열 좌표부터. 밴드는 「年次生」(입학년도 뒤 2자리) 단위
- 경제학부 완성본 `docs/data/sophia-economics-2026.json` 을 **스키마 견본**으로 쓴다

### 9-3. 충돌 방지 규칙

- **담당표에 없는 학교를 시작하려면 먼저 이 표에 행을 추가하는 PR**(=선점)을 올린다. 상대가 이미 맡은 학교는 안 만진다.
- `MASTERS-INDEX.md`는 둘 다 고치는 파일 → **자기 학교 행·섹션만** 수정, PR 올리기 직전 `git pull origin master`로 최신화. PR은 작게(학부 1~2개 단위).
- 새 함정을 만나면 매뉴얼 §9에 **추가**(지식은 문서에 쌓는다). 매뉴얼 본문 절차를 바꾸고 싶으면 상대에게 `@멘션`.
- 머지는 준희.

### 9-4. 태희 회신(2026-10-25)과 준희 측 답 (2026-10-28)
태희: **3행 전부 수락.** 맡기 전에 실제로 돌려본 결과도 함께 보내 줬다. 아래는 그 결과와 답이다.

1. **와세다 시라버스 = 두 회선 모두 불가.** 태희가 "준희 쪽에서 한 번 확인해 달라"고 했는데, 준희 PC에서는 이미 실패를 확인했다(2026-10-25, DATA-MANUAL §13-1). 원인은 지역 제한 또는 학내망 전용으로 보이나 확정은 못 한다.
   → 시라버스 크롤은 **보류**한다. 와세다 강의 데이터는 **학부별 「学科目配当表」 PDF 경로**로 간다(商 완료, PR #36). 담당은 그대로 준희.
2. **上智 PDF 도구 문제 — 해결됨.**
   - `render.mjs`가 `canvas` 패키지를 찾다 죽던 문제는 고쳤다(PR #36, 매뉴얼 §9-20). `git pull` 후 `npm install`만 하면 렌더된다. **poppler 설치는 필요 없다.**
   - poppler `pdftotext`가 일본어를 못 뽑은 원인은 CMap 데이터가 없어서다(§9-21). 우리 도구 `pdftext.mjs`·`rawxy.mjs`는 CMap을 써서 上智 経済 p3의 일본어를 정상으로 뽑는다.
   - 그래서 **매뉴얼 §5 순서대로 텍스트 추출이 1순위**이고, 렌더 이미지는 병합셀·중괄호 목시 확인용이다. 이미지를 읽어 옮겨 적는 방식은 오독 위험이 있으니 텍스트로 못 뽑는 쪽에만 쓴다.
   - 태희가 추가하려던 §9 함정("Windows에서는 poppler")은 §9-20·21로 대신 들어갔으니 따로 안 써도 된다.
3. **上智 구 밴드(「18～21年次生」) → 넣는다.** 매뉴얼 §7 「입학년도에 따라 요건이 다르면 파일을 밴드별로 나눈다」와 §12 「기존 밴드는 유지하고 새 밴드를 추가」 규칙 그대로다. 2021년 입학생은 2026년에 4학년이라 아직 재학 중이다.
   - 파일은 밴드 시작 연도로 따로 만든다: `sophia-<faculty>-2018.json`(`admissionYearMax: 2021`). 견본은 `meiji-management-2017.json`·`-2021.json`.
   - **上智 전체가 태희 담당**이므로 経済 구 밴드(`sophia-economics-2018.json`)도 태희가 넣는다. 태희가 3쪽에서 읽은 값(全学共通 必修2[体育2]·選択必修4·選択20 / 語学 必修4 / 学科 94 / 計124)은 준희 측 렌더에서도 같은 화면으로 확인했다.
4. **진행 계획 동의.** 神学部부터 1~2학부씩 `data/sophia-<faculty>-2026` PR, 他校 조사는 MASTERS-INDEX 「他校 10개교」표의 자기 행만 갱신.

## 10. 비공개 便覧을 어떻게 손에 넣나 (2026-10-28 준희 제기)

> "데이터 모으기 힘들다 했잖아 비공개여서. 이거 다른 시간표 앱에서 받아와 볼까?
> 아니면 직접 그 학교 학생한테 부탁하는 것도 하나의 방법이고. 좀 더 방법을 생각해보자.
> 일단 공개는 다 채우고. 태희랑 분업해서." — 준희

### 10-0. 🔴 먼저: 다른 시간표 앱에서 받아오는 건 안 된다
[CONTENT-OPS §8](CONTENT-OPS.md)의 강의평과 **같은 이유**다 — 타 앱의 이용약관·데이터베이스 권리·저작권.
스토어 신고 한 번이면 앱이 내려가는데, 얻는 건 우리가 어차피 다른 경로로 구할 수 있는 데이터다. **비용 대비가 나쁘다.**

> 💡 그리고 한 걸음 더 생각하면 — **그 앱들은 그 데이터를 어디서 가져왔을까?**
> 공개 시라버스면 **우리도 직접 크롤하면 되고**(합법), 학내 비공개면 **그쪽도 학생 기여로 모은 것**이다.
> 어느 쪽이든 **우리가 직접 할 수 있는 일**이지 가져올 이유가 없다.

### 10-1. 🟢 쓸 수 있는 경로 6가지 (비용이 낮은 순)

### 10-2. 🟢 학생에게 부탁하기 — 테스터 모집과 겸하면 공짜다
안드로이드 폐쇄테스트 **테스터 12명**을 어차피 모아야 한다([MY-TASKS.md](MY-TASKS.md)).
**그때 섭외 대상을 학부로 지정**하면 두 문제가 한 번에 풀린다.

- 우선 섭외: **메이지 理工 · 情コミ 학생** (지금 막혀 있는 2학부)
- 교환 조건이 자연스럽다: **"便覧 주면 그 학부 졸업요건 기능을 먼저 열어줄게"**
  → 상대에게 실제 이득이 있고, 우리는 데이터를 얻고, 그 사람은 테스터 겸 초기 유저가 된다
- 요청 문구는 간단하게: *"학부 便覧 PDF 한 부만 보내줄 수 있어? 앱에서 네 학부 졸업요건 계산 기능 만드는 데 쓸 거야"*
- ⚠️ **받은 PDF는 저장소에 커밋하지 않는다** (학내 자료). 추출한 **요건 JSON만** 커밋한다 —
  숫자·과목명은 사실 데이터라 문제없고, 원본 PDF는 로컬에만 둔다
