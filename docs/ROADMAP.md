## 3. Claude 세션 운영 원칙 (토큰 효율)

월 40~60세션이 아니라 **월 12~16세션으로 계획한 이유**가 이것.

1. **1세션 = 1기능 단위.** "시간표 저장 구현"처럼 커밋 하나로 끝나는 크기.
   세션이 길어져 컨텍스트가 커지면 요약 비용이 커지므로, 기능이 끝나면 세션도 끝냄
2. **컨텍스트는 문서로 외부화.** 아키텍처 결정·규칙은 CLAUDE.md와 docs/에 커밋
   → 매 세션 재설명 불필요 (이 문서 자체가 그 역할)
3. **검증은 저비용 수단부터.** `tsc --noEmit`(저렴) → 미리보기 스냅샷(중간) →
   스크린샷(비쌈) 순. 스크린샷은 UI 변경 시에만
4. **크롤러·스크립트류는 토큰 우대 작업.** 로컬 실행 결과만 확인하면 되므로
   미리보기 왕복이 없음 → 10월이 세션 수 대비 산출물이 가장 큰 달
5. **대형 작업(8월 전환)은 계획 세션 1회 분리.** 스키마·파일 목록을 먼저 확정하고
   구현 세션은 그 계획을 따라가기만 → 재작업 토큰 낭비 방지
6. **막히면 세션을 갈아탄다.** 같은 버그로 3회 이상 왕복하면 새 세션에서
   증상 요약부터 다시 시작하는 게 싸다

## 5. 지금 결정되어 있는 것 (재론 금지 목록)

- 익명성 유지 (단, 운영자는 투고자 특정 가능 — 법적 대응용 `authorUid` 보존)
- 이중 공간: 유학생 라운지(전국·개방) / 학교 게시판(단계별 인증)
- 인증은 verificationLevel 스위치 방식 — 초기 개방, 성장기에 조임
- 강의평은 구조화(별점·태그) + 자유텍스트 분리 (언어권 확장 대비)
- Penmark 유틸리티 따라하기(캘린더·투두) 금지
- 확산 축: 한국인 유학생 → 전체 유학생. 일본인은 다리 기능으로만
- **로그인 ≠ 대학인증** (2026-07-14 확정): 사용자의 본체는 uid. 이메일 등록(아무 메일 OK)은
  데이터 인계용 열쇠, Microsoft/학교메일 인증은 배지(verificationLevel) 획득 경로.
  두 경로를 합치지 않는다 — 대학 계정은 졸업 시 회수되므로 uid를 대학 계정에만 묶으면
  졸업생 데이터 접근이 끊김. 게스트→등록→인증의 3단 구조 유지
- **시간표 기본 공개범위 = friends** (2026-07-15 확정): 친구 시간표 열람·겹침 표시가
  앱의 핵심 가치이므로 기본값은 "친구에게 공개". 본인이 Phase 2 공개범위 UI에서
  private/department/public으로 변경 가능. 개인정보처리방침의 "본인이 공개 설정한
  시간표" 조항과 일치
- **공개 정보 분리** (2026-07-15 확정): users 본체(이메일·학업정보 포함)는 본인 전용,
  타인에게 보이는 정보는 usersPublic(닉네임·사진·학교·학부)만. GPA 등은 절대 미러 금지
- **학점 관리(졸업요건 추적) = 런칭 1.0 범위 밖 · 2-트랙 개발** (2026-07-21 확정):
  설계·상학부 마스터 추출은 완료([docs/CREDIT-TRACKING.md](CREDIT-TRACKING.md),
  [docs/data/meiji-commerce-2026.json](data/meiji-commerce-2026.json))이나 **구현은 런칭 후(Phase 3)**.
  결정 골자:
  - **3 데이터 소스 분리:** 便覧=룰북(요건·코스별 과목·단위 마스터) / 성적표=개인 이수 이력 /
    시라버스=실시간 개설(이미 크롤러 보유). 이 셋을 합쳐야 "학점 관리"가 됨.
  - **마스터 획득 2-트랙:**
    - **트랙 A (LLM 보조 authoring):** 便覧 PDF → LLM 초안 → **개발자/큐레이터 검수 → 공유 마스터(verified)**.
      LLM은 **오프라인 저작 보조만**(런타임 아님). 마스터는 `(학교×학부×입학년도)` 단위 · 소수 · 거의 불변 →
      **자동화가 아니라 재사용으로 확장.** 便覧은 규칙 파서 불가(세로표+학교마다 상이)라 LLM 초안이 정석.
    - **트랙 B (사용자 수작업):** 성적표 이수 이력은 **학생 手입력**(만능 폴백, 옵션: 텍스트레이어 PDF 규칙 파싱).
      미커버 학부 마스터는 학생이 비공개 手작성 → 검수 후 공유 승격.
  - **런타임은 결정론적 계산(LLM 0)** — 고위험 데이터라 감사 가능·프라이버시(성적 기기 밖 미전송) 우선.
    마스터 신뢰는 기존 강의 데이터의 `verified` + `confirms` 서브컬렉션(문서ID=uid, 1인1회) 메커니즘 재사용.
    (※ `confirmCount` 필드는 7/21에 제거됨 — 옛 설계 표현이 문서 곳곳에 남았을 수 있으니 confirms 기준으로 읽을 것)
  - **커버리지 전략:** 런칭 타깃 학교는 **공개 履修要項으로 선제 시딩**, 나머지는 업로드/크라우드 기여로 확장.
    큐레이터 = 초기 개발팀 → 성장기 "작성"에서 "승인(검수)"으로 역할 이동.
  - **아키텍처 가드레일 (2026-07-26 확정)** — [CREDIT-TRACKING.md §6](CREDIT-TRACKING.md) 참조. 골자:
    (1) 학점관리는 `便覧+성적표`로 자기완결하는 **독립 서브시스템** — 크롤러/시간표와 잇지 않음(시점 불일치).
    → **Phase 2에서 courses·리뷰·시간표 스키마를 학점관리 때문에 바꾸지 말 것.**
    (2) 저장은 **E2E 암호화 금고**(`users/{uid}/creditVault`, 복구 암호) — 서버 평문 성적 미보유,
    화면값은 계정(uid) 따라 기기 간 동일, usersPublic 미러 금지.
    (3) **schoolDomain "global" 부채 해소가 착수 선행 조건**(준희 복귀 후 조율, §6 기술부채).
