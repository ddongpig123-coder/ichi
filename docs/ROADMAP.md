## 3. Claude 세션 운영 원칙 (토큰 효율)

월 40~60세션이 아니라 **월 12~16세션으로 계획한 이유**가 이것.

1. **1세션 = 1기능 단위.** "시간표 저장 구현"처럼 커밋 하나로 끝나는 크기.
   세션이 길어져 컨텍스트가 커지면 요약 비용이 커지므로, 기능이 끝나면 세션도 끝냄
2. **컨텍스트는 문서로 외부화.** 아키텍처 결정·규칙은 CLAUDE.md와 docs/에 커밋
   → 매 세션 재설명 불필요 (이 문서 자체가 그 역할)
3. **검증은 저비용 수단부터.** `tsc --noEmit`(저렴) → 미리보기 스냅샷(중간) →
   스크린샷(비쌈) 순. 스크린샷은 UI 변경 시에만
4. **크롤러·스크립트류는 토큰 우대 작업.** 로컬 실행 결과만 확인하면 되므로
   미리보기 왕복이 없음 → 10월이 세션 수 대비 산출물이 가장 큰 달
5. **대형 작업(8월 전환)은 계획 세션 1회 분리.** 스키마·파일 목록을 먼저 확정하고
   구현 세션은 그 계획을 따라가기만 → 재작업 토큰 낭비 방지
6. **막히면 세션을 갈아탄다.** 같은 버그로 3회 이상 왕복하면 새 세션에서
   증상 요약부터 다시 시작하는 게 싸다

## 5. 지금 결정되어 있는 것 (재론 금지 목록)

- 익명성 유지 (단, 운영자는 투고자 특정 가능 — 법적 대응용 `authorUid` 보존)
- 이중 공간: 유학생 라운지(전국·개방) / 학교 게시판(단계별 인증)
- 인증은 verificationLevel 스위치 방식 — 초기 개방, 성장기에 조임
- 강의평은 구조화(별점·태그) + 자유텍스트 분리 (언어권 확장 대비)
- Penmark 유틸리티 따라하기(캘린더·투두) 금지
- 확산 축: 한국인 유학생 → 전체 유학생. 일본인은 다리 기능으로만
- **로그인 ≠ 대학인증** (2026-07-14 확정): 사용자의 본체는 uid. 이메일 등록(아무 메일 OK)은
  데이터 인계용 열쇠, Microsoft/학교메일 인증은 배지(verificationLevel) 획득 경로.
  두 경로를 합치지 않는다 — 대학 계정은 졸업 시 회수되므로 uid를 대학 계정에만 묶으면
  졸업생 데이터 접근이 끊김. 게스트→등록→인증의 3단 구조 유지
