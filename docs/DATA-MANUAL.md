# 데이터 매뉴얼 — 졸업요건(便覧)·강의 데이터를 매년 수집·검증·반영하는 표준 절차

> 작성 2026-10-24. **이 문서가 정본(source of truth)** 이다. 어떤 모델·어떤 세션이든 이 절차대로 한다.
> 새 접근을 시도하지 말 것. 막히면 **§9 함정**부터 확인하고, 그래도 안 되면 §10의 「미검증」으로 표시하고 멈춘다.
> 진행 현황은 [docs/data/MASTERS-INDEX.md](data/MASTERS-INDEX.md), 사람끼리의 분담은 [COLLAB-DATA-TAEHUI.md](COLLAB-DATA-TAEHUI.md).

## 0. 세션 시작 프롬프트 (복사해서 쓰기)

```
docs/DATA-MANUAL.md 를 읽고 그 절차대로만 진행해. 대상: <학교> <학부> <연도>.
새 접근 금지, 수치는 지어내지 말고 확실하지 않으면 "미검증"으로 남겨. 끝나면 MASTERS-INDEX 갱신 + PR.
```

## 1. 절대 원칙 (어기면 틀린 졸업 계산이 나간다)

1. **수치를 지어내지 않는다.** 출처에 없으면 `null` + `"미검증"` 표시. 추정값을 숫자로 쓰지 않는다.
2. **합계 검증이 통과해야 저장한다.** 영역 최저단위 합 == 졸업단위(§6). 안 맞으면 원인을 찾아 `_validation`에 산식을 쓴다.
3. **공개 자료만 쓴다.** 학생 포털(Oh-o!Meiji, Hoppii, manaba 등) 로그인은 하지 않는다. 비공개면 §10으로.
4. **눈으로 확인한다.** 병합셀·중괄호·○△표·2단 조판은 텍스트 추출로 판별이 안 된다 → `render.mjs`로 그 페이지를 PNG로 띄워 본다.
5. **출처 URL·연도·추출일을 `_meta`에 남긴다.** 다음 해에 "뭘 기준으로 한 값인지" 되짚어야 한다.
6. **브랜치 규칙**: `master` 최신화 → 작업 브랜치(`data/<학교>-<학부>-<연도>`) → PR. master 직접 push 금지. PR 머지·브랜치 삭제는 준희가 한다.
7. **앱 코드 변경은 심사 중엔 production OTA를 쏘지 않는다**(LAUNCH-RUNBOOK). JSON·docs는 언제든 머지 가능.

## 2. 전체 흐름 (두 파이프라인)

```
[A] 졸업요건 파이프라인 (학교×학부×입학년도)        [B] 강의 데이터 파이프라인 (학교×학부×연도×학기)
 §3 출처 찾기 → §4 받기 → §5 추출 → §6 검증         §11 크롤 → dry-run → Firestore 적재 → 건수 검증
 → §7 JSON 저장 → §8 앱 연동 → MASTERS-INDEX → PR    → 검색 확인 → scripts/README 갱신 → PR
```

두 파이프라인은 **매년 봄(便覧 발행·시라버스 공개 직후, 3~4월)** 에 §12 연간 체크리스트로 돌린다.

## 3. 출처 찾기 — 이 순서로, 하나 찾으면 멈춘다

| 순위 | 출처 | 신뢰도 | 비고 |
|---|---|---|---|
| ① | **학부 공식 사이트의 便覧/履修要項/履修要覧 PDF** (학생용 페이지) | 최상 | 배당표(과목→科目群·配当年次)까지 있음 |
| ② | **학칙 별표/学部則/학위정보 공개 페이지** (情報公開) | 상 | 영역별 최저단위는 정확. 배당년차 없음(§10) |
| ③ | 학부 공식 사이트의 卒業要件 HTML 페이지 | 상 | 법정·메이지 経営처럼 1페이지형. 그대로 전사 가능 |
| ④ | 커리큘럼 개요표·카리큘럼맵 PDF | 중 | 요건 수치의 교차검증용. 단독 출처로 쓰지 않는다 |

검색어: `<학교> <학부> 便覧 2026 pdf` / `履修要項` / `履修要覧` / `卒業要件 単位` / `学則 別表`.
학부 사이트의 「在学生の方」「シラバス・時間割」「事務室」 메뉴를 먼저 본다. 메이지는 10학부 URL이 MASTERS-INDEX 표에 있다.

**찾은 결과는 반드시 MASTERS-INDEX의 「便覧 공개 여부」표에 적는다** — 비공개여도 "확인했다"는 기록이 다음 해 시간을 아낀다.

## 4. 받기

```bash
# PowerShell Invoke-WebRequest는 Cloudflare(와세다 등)에 막힌다 → curl + 브라우저 UA + Referer
curl -sS -L --compressed -A "Mozilla/5.0 (Windows NT 10.0; Win64; x64) Chrome/131.0.0.0" \
  -H "Referer: <목록 페이지 URL>" -o <school>-<faculty>-<year>.pdf "<PDF URL>"
file <파일>.pdf      # "PDF document" 인지 확인 (HTML이 받아졌으면 챌린지 페이지)
```

- **정정표(正誤表/訂正)** 가 같이 올라와 있으면 **반드시 같이 받아** 요건표에 영향 있는지 본다.
- 목록 페이지가 JS로만 그려지면(上智) 브라우저 패널로 열어 링크를 뽑는다.
- 받은 PDF는 레포에 넣지 않는다(용량·저작권). URL만 `_meta.sourceUrl`에.

## 5. 추출 (순서 고정)

```bash
cd scripts/binran && npm install        # 최초 1회
node pdftext.mjs <pdf> > <name>.txt      # 1) 전체 텍스트
grep -n "卒業要件\|卒業に必要\|配当表\|科目一覧\|最低基準" <name>.txt   # 2) 요건표·배당표 페이지 찾기
node rawxy.mjs <pdf> <page>              # 3) 표의 열 경계(x) 잡기 — 헤더행과 과목행 2~3줄이면 충분
node render.mjs <pdf> <page> 2.6 p.png   # 4) 병합셀·○표·중괄호가 있으면 PNG로 확인
```

5) 가장 비슷한 `parsers/*.mjs`를 복사해 **X_* 좌표와 ZONE/DEPT 표만 바꾼다.** 파서 구조(행 묶기 → 헤더 상태전이 → 과목행 판정)는 바꾸지 않는다.
6) 실행 결과의 `courses / skipped / 必修 / 配当年次なし` 4개 숫자를 적어 둔다 → §6에서 쓴다.

**추출 규칙(모든 파서 공통)**
- 행 묶기: 같은 y ±2.5pt. 세로쓰기 사이드 견출(x≥580 등 표 바깥)은 **헤더 판정에서 제외**(§9-4).
- 과목행 판정: 「単位数 열에 숫자」 AND 「時間数 열에 숫자」. 둘 중 하나라도 없으면 헤더/주석.
- 필수 마크: ●○◎=必修, △=選択必修. 마크 열 위치는 학부마다 다르다(과목명 앞 접두 / 독립 셀 / 트랙별 2열).
- 配当年次: ○표면 **x좌표 bin**으로 학년 판정(개수로 판정 금지). 텍스트("1・2", "1～4", "履修開始年次 3年")면 전개.
- 병합셀(必要単位数 등)의 숫자는 **행과 무관하게 열 범위로 따로 수집**하고, 그룹 전환 **후에** 수집한다(§9-3).

## 6. 검증 체크리스트 — 전부 통과해야 §7로 간다

| # | 검사 | 통과 기준 |
|---|---|---|
| V1 | 영역 최저단위 합 == 졸업단위 | 정확히 일치. 안 맞으면 **원인을 찾아** `_validation`에 산식(중복산입·상한·잔여분) 기록. 메이지식이 아닌 학교(早稲田·法政)는 §9-6 |
| V2 | 必修 과목 단위 합 == 요건표의 必修 단위 | 학부/학과/트랙별로 전부 (예: 農芸化学 16과목=32=별표1 必修32) |
| V3 | 하위 영역 합 == 상위 영역 | subZones가 있으면 (예: 上智 学科科目 4+8+30+52=94) |
| V4 | 풀 ≥ 최저단위 | 배당표가 있으면 각 (학과, zone)의 개설 단위 합 ≥ 요건 최저단위 |
| V5 | 독립 출처와 교차검증 | 便覧 ↔ 학칙별표1 ↔ 공식 HTML 중 **2개 이상**이 같은 수치. 1개뿐이면 `_meta.crossCheck: "단일출처"` |
| V6 | 스킵 행 전수 확인 | `skipped`가 전부 표 헤더 조각인지 눈으로. 과목이 섞여 있으면 열 경계 수정 |
| V7 | 配当年次 누락 0 | 누락이 있으면 전부 留学関係科目처럼 "지정 없음"이 정상인 과목인지 확인 |
| V8 | zone id가 요건 마스터와 일치 | 배당표의 zone 값 집합 ⊆ `requirementMaster.zones[].id` (+최저0 구분은 `_meta.notes`) |

검증은 **node 한 줄 스크립트로 숫자를 찍어서** 한다. "맞는 것 같다"는 통과가 아니다.
실제로 잡힌 것들: 法 会社法Ⅰ 배당년차 오류(목시 전사), 文 6전공 必要単位 누락(병합셀 독립행), 法 5코스 중 2코스만 44(선수집 버그) — 전부 합계 검증이 없었으면 그냥 나갔다.

## 7. JSON 저장 — 스키마 고정

파일명 `docs/data/<school>-<faculty>-<year>.json` (요건) / `…-allocation-<year>.json` (배당표). 학교 키는 `meiji / waseda / hosei / sophia / …`(도메인 앞부분).

```jsonc
{
  "_meta": {
    "source": "明治大学 2026年度 法学部便覧 …",      // 사람 읽는 출처
    "sourceUrl": "https://…pdf",                    // 받은 URL (필수)
    "extractedAt": "2026-10-12",                    // 추출일 (필수)
    "school": "meiji", "schoolDomain": "meiji.ac.jp",
    "faculty": "law", "facultyNameJa": "法学部",
    "admissionYear": 2026, "appliesTo": "2026年度入学者（法律学科）", // 입학년도 밴드 (필수)
    "verifiedBy": "…어떻게 검증했는지 §6 결과…",
    "crossCheck": { "date": "…", "against": "…", "url": "…", "result": "…" }  // V5
  },
  "requirementMaster": {
    "totalRequired": 128,
    "zones": [ { "id": "kiso", "nameJa": "基礎科目群", "minUnits": 6, "rule": "all-required|min-units|composite|capped", "noteJa": "…" } ],
    // 학과별로 다르면 "byDepartment": true, "departments": [{ "id", "nameJa", "zones": [...] }]
    // 유학생/트랙별로 다르면 "tracks": [{ "id": "ryugakusei|domestic|…", "zones": [...] }]
  },
  "_validation": { "zoneSum": 128, "check": "6+12+16+2+24+8+44+16=128 ✓", "status": "verified" },
  "milestones": { "year4Min": {…}, "promotion": {…} },   // 있으면
  "specialRules": {…}, "courseMasters": {…}                 // 있으면
}
```

- `zone.id`는 **앱 `src/data/facultyMasters.ts`의 id와 1:1**. freezone(자유선택)은 id에 `freezone` 또는 `jiyu`를 포함(앱이 `/freezone|jiyu/i`로 판정).
- 입학년도에 따라 요건이 다르면 **파일을 밴드별로 나눈다**(`meiji-management-2017.json` / `-2021.json`). 하나의 파일에 두 밴드를 섞지 않는다.
- 배당표 JSON의 과목 레코드: `{ name, units, years:number[], mark:"必修"|"選択必修"|null, zone, kubunJa, scope|gakka, biko? }`. 便覧 그대로 보존(交換留学生·留学認定 등도 플래그로 남김). 앱 TS에서만 거른다.

## 8. 앱 연동 (메이지만 — 他校는 §10)

1. `src/data/facultyMasters.ts`: 밴드 추가(`admissionYearMax`로 구간) / 학과(`byDepartment`) / 코스·학과 필터(`canDepartments`) / 유학생 변동(`minUnitsRyugakusei`).
2. 배당표 → `src/data/allocation<Faculty>.ts` (빌더 예시: `scripts/binran/builders/`). 형식은 `AllocCourse { name, units, mark:"必修"|"選必"|null, years, zone, gakka? }`.
   - 최저단위 0이라 요건표에 없는 구분은 그냥 두면 **CAN에서 조용히 사라진다** → `<FACULTY>_CAN_EXTRA_ZONES`로 표시 구분을 넘긴다(농 卒論関係 사례).
   - 交換留学生 전용·留学認定枠·卒業要件外(교직·대학원)은 TS에서 제외.
3. `app/graduation.tsx`: `allocCourses` 분기 추가(학과면 `deptId`, 유학생이면 `isRyugakusei`, 코스면 `gakkaFilter`).
4. `npx tsc --noEmit` 통과 → 미리보기(`expo-web` 8090)에서 **해당 학부 선택 → 학과/트랙 전환 → CAN 과목이 바뀌는지** 확인. 스크린샷 또는 `innerText` 확인 결과를 PR 본문에.
5. i18n 안내문(`grad.soonSupported` 등)에 배당표 지원 학부 목록을 갱신.

## 11. 강의 데이터 파이프라인 (시라버스 크롤) — 메이지

정본은 [scripts/README.md](../scripts/README.md). 여기는 **매년 돌리는 순서와 검증**만.

```bash
cd scripts && npm install
node crawl-syllabus.mjs --category 12 --nendo 2027 --semester 10 --details   # 학부코드×학기, --details로 単位
node load-firestore.mjs --file output/courses-12-2027-10.json --dry-run       # 키 없이 형식·중복 검증
node load-firestore.mjs --file output/courses-12-2027-10.json --dept 12        # 적재(서비스계정 키 필요, 준희 PC)
```

**검증**: ① dry-run 건수 = 크롤 건수 ② 학부별 Firestore 문서 수 = 春·秋 파일 id 합집합(通年은 양쪽에 들어가 중복 제거됨이 정상) ③ 앱에서 그 학부 선택 후 흔한 단어(マーケ/英語/演習)로 검색해 결과가 뜨는지.

**지금 알려진 빈 곳(2026-10-24 점검)** — 채우려면 아래 순서:
1. ~~学部間共通 과목이 아예 없음~~ → **해소(2026-10-25)**. 검색폼 category에서 **81 共通外国語 / 82 資格課程 / 83 情報関係 / 84 留学生·国際連携 / 87 国際協力人材育成** 확인 → 봄·가을 `--details` 크롤 → dry-run → 적재. **1,406건 추가**(81: 426 / 82: 580 / 83: 251 / 84: 149 / 87: 0건 개설) → Firestore 총 21,078, `count-firestore.mjs`로 15구분 전부 일치. 앱은 `departments.ts`에 81~84 칩 4개(87은 0건이라 미노출). 매년 재크롤 시 **학부 10개 + 이 5개 코드**를 같이 돌린다.
2. ~~흔한 단어 검색이 0건~~ → **해소(2026-10-25, PR #28, 태희)**. 처음 가정(gram 선택)은 틀렸고 실제 원인은 **필터 순서**였다: 후보 300건 상한이 연도·학기 필터보다 먼저 걸려 다른 학기 과목으로 채워진 뒤 깎임(理工 「英語」 235건 중 169건만 = 28% 누락). 연도·학기를 **서버 측 `where`** 로 올리고 상한 500. 복합 인덱스 불필요(실데이터 확인). **교훈: "0건"과 "잘림"은 다르다 — 실측 건수 vs 표시 건수를 비교하라.**
3. ~~1글자 검색 0건~~ → **안내로 확정**(PR #28): 1글자면 「2文字以上で検索してください」. 1-gram 적재는 하지 않는다(양쪽 `makeBigrams`는 그대로 2-gram).
4. 🟡 **의도적 스킵**: 요일·교시 없는 과목(집중강의·実習)과 日曜 과목 — `Course` 타입이 day/period 필수. 검색에 노출하려면 타입 확장(태희 창구 `src/types/`)
5. ~~総合数理 秋 167건 미적재 가능성~~ → **해소**. `node scripts/count-firestore.mjs`(키 필요, 읽기 전용)로 학부별 로컬 고유 id vs Firestore 문서 수를 찍어 10학부 전부 일치(19,672) 확인(2026-10-25). 매년 적재 후 이 스크립트가 검증 ②다.
6. ⚪ **他校 강의 데이터 0건** — 학교마다 시라버스 구조가 달라 **대학별 크롤러 분리** 필요(§13)

## 13. 他校 확장 순서 (앱 학교 목록 10개교 기준)

MASTERS-INDEX 「他校 10개교 공개본 전수 조사」표가 현황.
**확정 방침(2026-10-25, 공문 §8-5): 他校는 "1개교 완전 지원"을 먼저 한다 — 졸업요건 + 강의 데이터(시라버스 크롤) + 앱 학교 분기를 한 묶음으로.** 첫 대상은 **早稲田**(商 요건 완료·학부별 요항 공개). 졸업요건만 쌓고 앱에 붙이면 "검색은 안 되는 반쪽"이 되므로, 요건 JSON 양산(上智 9학부·法政 39건 승격)은 계속하되 **앱 연동은 早稲田 패턴이 선 뒤에** 복제한다.
각 학교의 첫 학부는 **반드시 수동 목시 검증**을 거쳐 그 학교의 표 셈법(§9-6)을 `_validation`에 확정한 뒤 나머지 학부로 양산한다.
他校 시라버스 크롤러는 학교마다 구조가 달라 **학교별 파서를 `scripts/crawl-<school>.mjs`로 분리**하고, 출력은 반드시 `Course` 타입(§11)을 따른다.
