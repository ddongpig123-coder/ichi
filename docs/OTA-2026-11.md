## 0. 전제 — 이 OTA가 닿는 바이너리와 호환성 (2026-11-05 확인)

| 바이너리 | 커밋 | runtimeVersion | 비고 |
|---|---|---|---|
| iOS 빌드 5 (심사 중 · 승인되면 App Store) | `6ba8c4b` | 1.0.0 (`appVersion` 정책) | S2·S3 포함 |
| iOS 빌드 4 (TestFlight, 준희 폰) | `7463bab` | 1.0.0 | S2·S3 **전** |
| Android 비공개 `alpha` (테스터 12명) | `159a5b3` | 1.0.0 | S2·S3 **전**. master보다 **85커밋** 뒤 |

- 세 바이너리 모두 채널 `production`·runtimeVersion 1.0.0 → **OTA 한 번으로 전부 갱신된다.** 안드로이드 테스터에게도 간다.
- 네이티브 의존성 변화: `6ba8c4b → master` **없음**. `159a5b3 → master`는 `@expo/vector-icons` 추가뿐(Expo SDK 내장 패키지, JS·폰트 에셋이라 OTA 가능 — S1 때 확인). `app.json`·`eas.json` 변화 없음 → **재빌드 불필요.**
- 🔴 **규칙을 조일 때 확인할 것은 「OTA가 퍼졌나」만이 아니라 「스토어 빌드에 내장된 코드가 새 규칙과 맞나」다** (2026-11-10).
  OTA는 「켤 때 받아 두고 **다음 실행**부터 적용」이라, **새로 설치한 사람의 첫 실행은 위 표의 내장 코드**로 돈다.
  내장 코드가 안 보내는 필드를 규칙이 필수로 요구하면, 새 유저는 설치 직후 그 기능이 실패한다(두 번째 실행부터 정상).
  예: 댓글 수 단계2(`lastCommentId` 필수)는 빌드 5 내장 코드가 안 보내므로 **새 iOS 빌드 이후**에 배포한다
- 🔴 **새 네이티브 부품(1.1.0 빌드에 새로 들어가는 것: 사진 선택·푸시 알림·위젯 …)을 쓰는 코드도 OTA 로 옛 바이너리(1.0.0)에 간다** (2026-11-14).
  옛 앱에는 그 부품이 없어서, 파일 맨 위에서 `import` 하면 **켜자마자 멈춘다.**
  → `requireOptionalNativeModule("모듈이름")`(from `expo`)으로 있는지 보고, 없으면 입구를 숨긴다. 패키지는 있을 때만 함수 안에서 `require`.
  본보기: `src/services/timetableOcrService.ts` 의 `canReadTimetableImage`
- ⚠️ 구 바이너리(빌드 4·Android alpha)는 **S3 전 코드**라 쪽지를 `schools/{sd}/chats`에 쓴다. OTA 뒤에는 `chats/` 최상위를 읽으므로 **기존 쪽지방이 안 보인다** → §4의 마이그레이션 스크립트를 OTA 직후부터 **반복** 실행.

> 커밋 안 한 변경 없음·타입 검사를 확인하고, 커밋을 보여 준 뒤 `y` 를 받아야 실행된다. 하나라도 걸리면 아무것도 안 한다.
> `npm run deploy:rules` → `npm run deploy:web` → `npm run ota -- "1.0.x: 내용"` (항상 `cd ~/ichi` 에서. `--environment production` 자동)

> ✅ **2026-11-06 실행 완료(준희)**: 0(규칙) → 2-2(웹) → 3(OTA) → 5(실기기). Claude 세션에서 확인: 웹 번들 새 해시, `/add-friend` 페이지 정상, 배포 웹에서 스크랩 쓰기·목록 반영 성공(= 규칙 배포 확인). `eas update:list`는 세션에서 못 봄(EAS 로그인 없음). 남은 건 §5 운영과 7번(#50).

```
0. 규칙 배포(지금 master의 규칙 = 加算만): npx firebase-tools deploy --only firestore:rules      ← 준희 직접(정지선)
```
