## 4. OTA 당일 순서 (승인 메일 → 그날)

```
1. master 최신 확인: git log --oneline HEAD..origin/master 가 비어 있어야. npx tsc --noEmit 통과
2. 미리보기(8090) 또는 실기기에서: 게시판 목록 · 숲 · 글쓰기 · 쪽지 · 졸업요건(情コミ CAN) 한 바퀴
2-2. npm run deploy:web                                                                      ← 준희 직접(정지선)
     초대 링크가 가리키는 웹 /add-friend 페이지를 OTA보다 먼저 올린다.
     확인: https://ichi-6b8f7.web.app/add-friend?u=test&k=test 가 「無効な招待リンク」면 OK
3. eas update --branch production --message "1.0.1: QA 수정·검색 색인·情コミ CAN·초대 링크·(S4)"  ← 준희 직접(정지선)
4. eas update:list --branch production 로 올라간 것 확인
5. 실기기: 앱을 완전히 닫고 2번 실행(1회차에 받고 2회차에 적용) → 바뀐 화면 확인
6. 안드로이드 테스터에게 "앱 한 번 껐다 켜 주세요" 공지(14일 카운트와 무관)
7. 🔁 그 뒤 「규칙 배포·OTA 순서」 4번: #50 리베이스 → 머지 → 규칙 배포(친구 수락 없는 관계 차단·좋아요 1인 1회)
   ⚠️ #50에 초대 토큰 경로(INVITE-LINK §3)가 들어 있어야 한다. 없이 배포하면 초대 링크가 전부 거부된다
```

문제가 있으면 **롤백**: `eas update:republish --branch production` 으로 직전 업데이트를 다시 올린다(= 빌드 5 JS로 복귀). 네이티브는 손대지 않는다.
