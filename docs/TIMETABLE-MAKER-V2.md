# 時間割メーカー v2 — 질문에 답하면 시간표가 나오는 단계형 설계 (2026-11-05 준희 제안 → 구성안)

> 현행(10/20 추가, `app/timetable-wizard.tsx` + `src/utils/timetableWizard.ts`)은 기능은 맞는데 **설명이 없어 뭘 하는지 모른다**(준희 실사용 피드백).
> 핵심 로직(겹치지 않는 조합 열거·정렬)은 그대로 쓰고 **화면을 질문→선택→다음 단계로 재구성**한다. 규칙·타입 변경 없음 → **OTA**. 세션은 S9(시간표 묶음).
> 아래 「데이터 출처」는 코드에서 확인한 사실. 없는 것은 「없음」으로 적었다 — 지어내지 않는다.

## 0. 한 줄 정의
**「이번 학기 목표 학점을 정하고, 꼭 들을 수업을 고르면, 시간이 겹치지 않는 시간표 후보를 만들어 주는 도구」.**
입구 버튼은 「メーカー」 한 단어 대신 **「時間割を自動で組む」** 로, 첫 화면에 이 한 줄을 그대로 보여준다.

## 1. 단계 흐름 (5단계, 한 화면에 질문 하나)

```
[0 시작] 한 줄 설명 + 학기 확인(2026 春)          ─ 학교·학부가 없으면 여기서 고르게
   ↓
[1 목표 학점] 「今学期、何単位取りますか？」        ─ 칩 16·18·20·22·24 + 직접 입력. 상한이 있으면 「半期上限 24」 표시
   ↓
[2 꼭 들을 수업] 「必ず入れる授業を選んでください」   ─ ① 便覧 필수(학년 맞는 것) 자동 제안 ② 검색으로 추가. ★ 토글
   ↓
[3 더 듣고 싶은 수업(임의)] 「他に受けたい授業」      ─ 검색해서 후보에 담기. 건너뛰기 가능
   ↓
[4 조합 중 → 결과] 「組み合わせています…」 → 카드 목록  ─ 미니 시간표 + 지표 배지 + 정렬 칩
   ↓
[5 확정] 「これにする」 → 「時間割を置き換えますか？」 → 완료 → 「時間割を見る」
```
- 상단에 **진행 점 5개**. 뒤로 가도 입력은 유지(화면 state). 앱을 껐다 켜도 후보가 남게 **AsyncStorage에 임시 저장**(학기키별).
- 각 단계 하단에 **다음 버튼 1개**, 조건이 안 되면 비활성 + 이유 1줄(예: 「必須の授業が時間で重なっています」).

## 2. 단계별 상세 — 무엇을 보여주고, 어디서 가져오나

### [1] 목표 학점
| 요소 | 내용 | 출처 (코드 확인) |
|---|---|---|
| 입력 | 숫자 1개. 내부적으로 **목표±2 범위**로 검색(현행 min/max 방식 유지, 사용자에겐 숨김). 0건이면 자동으로 ±4로 넓혀 재시도 후 「範囲を広げました」 표시 | `generateTimetables(min,max)` 그대로 |
| 상한 표시 | 「半期上限 24単位（便覧）」 | 🔴 **앱 마스터에 학기 상한 데이터가 없다.** JSON에 있는 건 情コミ(24)·早稲田 商뿐. → **데이터 작업: 메이지 10학부 便覧의 履修上限을 `facultyMasters` 밴드에 `semesterCap` 추가**(DATA-MANUAL 절차, 출처 명시). 없는 학부는 상한 문구를 **표시하지 않는다**(일반값 24를 지어 쓰지 않음) |
| 학년 | 「あなたは何年生？」를 여기서 같이 묻는다(1~4). 프로필 입학연도가 있으면 자동 계산해 기본값으로 | `gradeFromAdmissionYear` (졸업요건 화면과 동일) |

### [2] 꼭 들을 수업 — 便覧 필수 자동 제안이 v2의 핵심
| 요소 | 내용 | 출처 |
|---|---|---|
| ① 必修 제안 목록 | 「あなたの学部・学年の必修（便覧より）」. 각 줄: 과목명 · 단위 · 이번 학기 개설 분반(요일·교시·교원) 선택 | 배당표 TS의 `mark: "必修"` + `years`에 현재 학년 포함 → 과목명으로 이번 학기 강의(`searchCourses`)를 찾아 분반을 붙인다 |
| 커버리지 | 必修 마크가 있는 학부: **農 124 · 総合数理 121 · 法 32 · 政経 24 · 国際日本 23 · 経営 6 · 情コミ 2**. **文·商은 0**(便覧에 마크가 없거나 미추출) → 그 학부는 ①을 숨기고 ②만 | `src/data/allocation*.ts` 집계(2026-11-05) |
| 이름 매칭 | 便覧 과목명 ↔ 시라버스 강의명을 NFKC·공백 제거 후 **완전 일치 → 앞부분 일치** 순으로 연결. 못 찾으면 「今学期の開講が見つかりません（検索で追加）」 | 매칭 유틸 신규(`src/utils/`). 분반이 여러 개면 전부 보여주고 하나 고르게 |
| ② 검색 추가 | 현행 검색 UI 재사용. 추가한 것은 기본 ★(필수). ★ 해제하면 [3]의 후보로 내려감 | `searchCourses` |
| 검증 | 필수끼리 겹치면 즉시 빨간 줄 + 「どちらかを外してください」. 필수 합계가 목표+2를 넘으면 경고 | `generateTimetables`의 `requiredConflict` 로직 재사용 |

### [3] 더 듣고 싶은 수업 (건너뛰기 가능)
- 현행 「候補に追加」. 후보가 0개면 결과는 필수만으로 1개 나오므로 **건너뛰어도 동작**한다.
- 🟡 **「추천」은 v2에 넣지 않는다.** 근거 데이터가 아직 없다: 강의평 평균(`fetchCourseReviews`)은 강의 1개당 읽기 1회라 후보 수십 개에 쓰기엔 비용이 크고, 「같은 학부가 많이 담는 강의」 집계는 존재하지 않는다. v3 후보(§6).

### [4] 결과 카드
| 배지 | 정의 | 계산 |
|---|---|---|
| 単位 | 조합 합계 | 현행 `totalCredits` |
| 空きコマ n | 같은 요일 첫 수업~마지막 수업 사이 빈 교시 합 | 현행 `gapCount` |
| **1限 n** 🆕 | 1교시 수업 수 | slots 중 period===1 |
| **登校 n日** 🆕 | 수업 있는 요일 수 | distinct day |
| **土曜 あり** 🆕 | 토요일 수업 여부 | day==="土" |
| **メディア n** 🆕 | 미디어(온디맨드) 수업 수 | 배당표 `media: true`를 이름 매칭으로 붙임. 커버리지: **農 48 · 情コミ 44 · 総合数理 2, 나머지 0** → 데이터 없는 학부는 배지를 숨김 |
| 必修 ○/○ | 便覧 필수 중 포함된 수 | [2]①과 대조 |
- **정렬 칩**: 「空きが少ない」(기본) · 「1限が少ない」 · 「登校日が少ない」 · 「単位が多い」. 현행 정렬(단위 많은 순→공강 적은 순)을 칩으로 바꿔 끼운다.
- 결과 상한 30·탐색 상한 20만 노드는 유지. 잘렸으면 「上位のみ表示」(현행).
- 0건이면 「条件に合う組み合わせがありません」 + **원인별 제안**: 범위 넓히기(자동 재시도 후에도 0이면) / 필수 1개 빼기 / 후보 추가. 버튼으로 해당 단계로 되돌아감.

## 5. 결정 (2026-11-05 준희)
1. ✅ 목표 학점은 **숫자 1개(+내부 ±2)**. 최소~최대 2칸 폐지.
2. 🟡 기본 정렬: 준희 답은 「공강이 많은 순」. 한국어 「공강」은 **수업 없는 날(공강일)** 과 **수업 사이 빈 교시** 두 뜻이 있어
   앱에선 둘을 나눈다 — 「登校日が少ない」(= 공강일 많음) 와 「空きコマが少ない」(= 빈 교시 적음). **기본 = 登校日が少ない → 같으면 空きコマが少ない** 로 두고 준희 확인 대기.
3. ✅ **시간표 점수(I-1) 유지** — 배지로 대체하지 않고 **점수를 따로 둔다.** 결과 카드마다 점수 표시 + 홈 시간표에도 표시. 마케팅 소재(「〇点の時間割」 공유)로 쓴다 → §7.
4. ✅ 학기 상한을 모르는 학부에는 상한 문구를 **표시하지 않는다**.

## 7. 時間割スコア (I-1) — 정의안
> 점수만, 칭호 없음(DECISIONS 2026-10-28). **높을수록 여유로운 시간표, 낮을수록 빡센 시간표.** 마케팅에서 「時間割スコア30点の人の時間割」「ハーマイオニー級」 같은 소재로 쓰려면 낮은 점수가 "웃기게 고생스러운" 쪽이어야 한다.

| 항목 | 점수 | 이유 |
|---|---|---|
| 시작 | **100** | |
| 1限 수업 | **−6 / 1코마** | 아침 |
| 토요일 수업 | **−10 / 1코마** | 주말 |
| 등교일 | **3일까지 0, 4일 −5, 5일 −12, 6일 −20** | 공강일이 줄수록 급격히 |
| 빈 교시(空きコマ) | **−3 / 1코마** | 하루 안의 죽은 시간 |
| 5限 이후 수업 | **−3 / 1코마** | 저녁 |
| 하루 4교시 이상 연속 | **−4 / 해당일** | 점심도 못 먹는 날 |
| 하루 1코마만 있는 날 | **−4 / 해당일** | 한 수업 때문에 등교 |
| 범위 | **0~100으로 고정(clamp)** | |

- 계산은 `ClassSession[]`만으로 가능(요일·교시) → 메이커 결과 카드와 홈 시간표 양쪽에서 같은 함수(`src/utils/timetableScore.ts`) 사용. 강의 데이터·규칙 불필요.
- 표시: 결과 카드 우상단 「スコア 72」, 홈 시간표 상단 작은 배지. 탭하면 감점 내역 팝업(「1限 ×2 −12 / 登校5日 −12 …」) — 점수의 근거가 보여야 납득한다.
- 마케팅 연결: S9의 **「시간표 이미지로 저장」(QA 10-①)** 결과 이미지에 점수를 같이 찍는다 → 그대로 카드뉴스·X 소재(MARKETING-2026-11 「究極の2択」류와 묶음). 점수 공식은 공개 저장소에 있으므로 "비밀 알고리즘" 식 홍보는 하지 않는다.
- 가중치는 안이다. 실제 시간표 몇 개로 돌려보고 「30점이 정말 빡센가」를 눈으로 확인한 뒤 조정(S9 구현 때).
