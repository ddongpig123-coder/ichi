# 앱 안 리뷰 요청 팝업 (1.2 새 빌드) — 2026-11-26 준희 결정

> **왜**: 1.1.0 공개 뒤 지인 리뷰가 작성자에게도 안 보이는 일이 생겼다(제출 누락·Apple 필터 추정).
> 지인에게 몰아서 부탁하는 방식은 Apple 필터에 걸리고 계정 리스크도 있다 → **실제 사용자에게, 만족한 순간에** Apple·Google 공식 팝업으로 받는다.
>
> **트랙**: `expo-store-review` 는 **새 네이티브 모듈** → OTA 불가, **1.2 새 빌드**에 넣는다([RELEASE-PLAN 「다음 새 빌드 때 할 것」](RELEASE-PLAN-2026-12.md)).
> 🟢 단, §4 의 「アプリを評価する」 메뉴(스토어 링크)는 JS 만이라 **지금 OTA 로 먼저 낼 수 있다.**

## 1. 꼭 지켜야 할 플랫폼 규칙 (어기면 심사 리젝·정책 위반)

| 규칙 | 내용 |
|---|---|
| **공식 API 만** | iOS 심사지침 5.6.1 — 리뷰 요청은 Apple 제공 API(`SKStoreReviewController`, = `expo-store-review` 의 `requestReview()`)로만. 직접 만든 별점 팝업 금지 |
| **사전 질문 금지 (review gating)** | 「この アプリ、気に入りましたか？」 → 「はい」면 리뷰, 「いいえ」면 문의 폼 같은 **걸러내기 금지**. Apple·Google 둘 다 금지 |
| **보상 금지** | 리뷰 대가로 포인트·기능 해제 등 금지 |
| **표시 여부는 OS 가 결정** | iOS 는 **1년(365일)에 최대 3번**만 실제로 뜬다. 호출해도 안 뜰 수 있고, 떴는지·별점 몇 개인지 **앱은 알 수 없다** |
| **버튼으로 띄우지 않기** | 「評価する」 버튼을 눌렀는데 OS 가 팝업을 안 띄우면 아무 반응이 없는 것처럼 보인다 → 버튼은 **스토어 리뷰 페이지 링크**(§4)로 |
| **시험판에선 안 뜸** | iOS TestFlight 에서는 안 뜬다(개발 빌드에서는 항상 뜸). Android 는 Play 스토어에서 받은 앱에서만 뜬다 → 실기기 확인은 개발 빌드 / Play 내부 테스트 트랙으로 |

> Google Play In-App Review 의 횟수 제한은 Google 이 숫자를 공개하지 않는다. 같은 조건 로직을 그대로 쓴다.

## 2. 타이밍 — 「성공 직후 + 충분히 써 본 사람 + 흐름을 끊지 않을 때」

### 2-1. 띄우는 순간 (트리거 후보, 위가 우선)
| # | 순간 | 이유 |
|---|---|---|
| T1 | **AI 시간표 읽기 → 시간표 저장 성공** 직후 | 이 앱의 제일 큰 「와」 순간. 홍보 문구와도 일치 |
| T2 | **시간표 저장 성공**(수동 입력, 과목 3개 이상 들어간 상태) 직후 | 한 학기를 다 넣은 순간 = 성취감 최대 |
| T3 | **친구 추가 성공** 뒤, 친구와 겹치는 수업을 처음 본 순간 | 사회적 가치가 체감되는 순간 |
| T4 | **졸업 요건 계산 결과**를 보고 화면을 닫을 때 | 데이터 있는 학교만. 「남은 학점」을 알게 된 순간 |

- 성공 토스트가 사라진 뒤 **약 1.5초 늦게** 호출(저장 완료 메시지와 겹치지 않게)
- 1번 실행에 **최대 1번만 시도**

### 2-2. 조건 (전부 만족할 때만 T1~T4 에서 호출)
| 조건 | 값(초안) | 이유 |
|---|---|---|
| 첫 실행 후 경과 | **3일 이상** | 깔자마자 묻지 않는다 |
| 앱을 연 날 수(서로 다른 날) | **3일 이상** | 한 번 써 보고 끝난 사람 제외 |
| 직전 요청 이후 | **120일 이상** | 1년 3번 한도를 학기마다(4월·9월 시즌) 나눠 쓴다 |
| 같은 앱 버전 | **버전당 1번** | 업데이트마다 한 번이면 충분 |
| 최근 오류 | 이번 실행에서 저장 실패·네트워크 오류가 없었을 것 | 짜증난 순간 피하기 |
| 게스트 여부 | 상관없음 | 리뷰는 Apple ID/Google 계정으로 쓰기 때문 |

### 2-3. 절대 띄우지 않는 곳
- 앱 시작 직후 · 온보딩 · 튜토리얼 팝업 위
- 글/댓글/쪽지 **작성 중**, 쪽지 대화방 안
- 신고·차단 직후, 오류 메시지 직후
- 푸시 알림·초대 링크를 눌러 들어온 직후(목적이 따로 있음)
- 위젯에서 들어온 직후

### 2-4. 시즌 메모
- 리뷰가 제일 필요한 건 **3~4월 신입생 시즌**(새 사용자가 스토어 페이지를 볼 때). 1.2 가 그 전에 나가야 3월 전에 리뷰가 쌓인다
- 120일 간격이면 「4월 시간표 짤 때 1번 · 9월 시간표 짤 때 1번」이 자연스럽게 된다

## 3. 구현 메모 (1.2 때 이대로)

- 🔴 **AGENTS.md 네이티브 모듈 규칙**: 맨 위 `import` 금지. `requireOptionalNativeModule` 로 있는지 확인 → 없으면(옛 1.1.0 앱) **아무것도 안 함**, 있을 때만 함수 안에서 `require('expo-store-review')`. 본보기 `src/services/timetableOcrService.ts`
  (모듈 이름은 구현 때 **Expo SDK 57 문서**로 확인)
- 새 파일 `src/services/storeReviewService.ts` 하나에 모은다
  - `recordAppOpen()` — 앱 시작 시 「연 날」 기록
  - `maybeRequestReview(trigger: "ocrSaved" | "timetableSaved" | "friendOverlap" | "graduationViewed")` — §2-2 조건 검사 후 호출
  - `noteError()` — 이번 실행에서 오류가 났음을 기록
- 저장은 **단말 로컬(AsyncStorage)** — `firstOpenAt`, `openDays`(최근 날짜 몇 개), `lastRequestAt`, `lastRequestVersion`. 서버·Firestore 불필요 → **규칙 변경 없음**
- `StoreReview.isAvailableAsync()` 가 false 면 조용히 끝낸다(웹 포함)
- 조건 값(3일·3일·120일)은 상수 한 곳에. 나중에 숫자만 바꿔 OTA 로 조정 가능

## 4. 지금 OTA 로 먼저 낼 수 있는 것 — 「アプリを評価する」 메뉴

- 프로필(설정) 화면에 항목 하나: **「アプリを評価する」**
- 누르면 스토어 리뷰 화면을 연다(`Linking.openURL`, 네이티브 모듈 불필요)
  - iOS: `https://apps.apple.com/app/id6825671804?action=write-review`
  - Android: `https://play.google.com/store/apps/details?id=jp.timetable.app`
- 웹에서는 숨기거나 두 링크를 다 보여 준다
- 이건 언제 눌러도 확실히 동작하므로 1.2 팝업과 역할이 겹치지 않는다(팝업 = 우리가 먼저 묻기 / 메뉴 = 사용자가 원할 때)

- 앱은 팝업이 떴는지 모르므로 「호출 횟수」만 로그로 셀 수 있다(필요하면)
