# 학점(単位) 관리 시스템 설계 노트 — 요람·성적표 분석 결과

> 원본: 2026년도 商学部便覧(182p) + 成績通知書 샘플 (분석 2026-07-19)
> 목표: 사용자의 코스 선택·이수 이력 기반 "개인 맞춤 졸업 요건 추적"
> 성적표의 개인 정보는 이 문서에 기록하지 않는다 (구조만).

## 1. 확인된 사실 (상학부 기준)

### 졸업 요건 구조 (便覧 인쇄 p6, 2026년도 입학생)
합계 **126単位** 이상 + 영역별 최소치를 전부 충족:

| 영역 | 최소単位 | 비고 |
|---|---|---|
| ①基礎教育科目 | 8 | 基礎演習2·文章表現2·経済学A/B4 전부 필수 |
| ②外国語 必修 | 16 | 既習(영어)8 + 初習(1개 언어)8. 선택분은 프리존 |
| ③総合教育+④総合学際演習 | 24 | 文化と芸術/地域と社会/人間と自然 각 4 이상 포함. 유학생은 日本事情A~F 8単位 산입 가능 |
| ⑤保健体育 必修 | 2 | 体育・スポーツ実習A·B |
| ⑥基本科目 | 16 | 商学専門演習(2年)은 여기 소속 |
| ⑦商学専門演習(3·4年)+⑧基幹科目 | 48 | **自コース 28 이상 + 基幹英語 4 이상 포함** |
| フリーゾーン | 12 | 임의 선택(외국어 선택분·応用展開·타학부 등) |

### ⚠️ 요건은 입학년도별로 다르다
성적표 샘플(2021년 입학)의 필요 합계는 **134**, 2026년도 요람은 **126**.
요람 자체가 "입학~졸업까지 유효"라고 명시 → **요건 마스터는 (학부, 입학년도) 단위로 버전 관리** 필수.

### 코스(専門コース) 체계
- 7개 코스, **2학년 가을학기(2年次秋学期)에 선택**(便覧 인쇄 p5 확정 — 종전 "2학년 진급 시 추정" 정정).
  선택은 2학년부터 시작하는 「商学専門演習」선택과 연동, 3~4학년부터 자코스 基幹科目 본격 이수.
- **7개 코스 전부 확정:** アプライド・エコノミクス / マーケティング / ファイナンス＆インシュアランス /
  グローバル・ビジネス / マネジメント / アカウンティング / **クリエイティブ・ビジネス**(누락됐던 7번째)
- 便覧 인쇄 p25~28에 **코스별 自コース科目 전체 목록**(과목명·配当学年·単位) — 모두 3~4년 배당·2단위.
  → **[docs/data/meiji-commerce-2026.json](data/meiji-commerce-2026.json) 에 JSON화 완료** (7코스 240 항목, 코스 간 중복 포함).
- "自コース 28単位" 판정은 이 목록 소속 여부로 계산. 단, **基幹英語로 인정받은 과목은 自コース 28에 불산입**(아래 §5).

### 과목 코드 체계 (성적표에서 확인)
`00-12X###` 형식. `12`=商学部, 알파벳=영역:
`A`=基礎(経済学) `B`=総合教育 `C`=既習外国語 `H`=初習外国語 `I`=保健体育
`J`=基本科目 `K`=基幹科目 `L`=応用展開...
→ 코드 첫 알파벳으로 영역을 대략 추정할 수 있으나 **코드는 성적표에만 있고 배당표에는 없다**(아래 정정).
크롤러의 courseNumber((CO)CMM311J 형식)와는 별개 체계.

> **⚠️ 정정 (2026-07-19 추출):** 배당표(p29~39)에는 **과목코드 열이 없다.** 대신 각 과목이
> `科目区分(群)` 아래에 직접 배치되어 있어 **분류의 정석은 "코드→영역"이 아니라 "과목명→영역"**이다.
> 배당표가 과목명↔영역의 권위 있는 원본이며, 코드는 성적표 파싱 시의 보조 힌트로만 쓴다.

### 성적표(成績通知書) 구조
- 영역별로 그룹핑된 이수 과목 목록: 코드·과목명·単位·평가(S/A/B/C/F)·GP·연도·담당자
- **単位修得状況 표가 이미 내장**: 영역×(必要, 연도별 취득, 合計) — 우리가 만들 대시보드의 원형
- F(불합격)는 単位 미산입·재수강 행 별도 존재. GPA·GP총계 기재
- 시사점: 이수 이력 입력 UX는 "성적표를 보며 그대로 입력"이 가능한 구조.
  장래에는 PDF 업로드 → 자동 파싱도 현실적 (레이아웃이 정형적)

## 2. 데이터 모델 초안

```
requirementMasters/{schoolDomain}/{faculty}/{admissionYear}   ← 요람에서 추출
  { totalRequired, zones: [ { id, nameJa, nameKo, minUnits,
      rule: "all-required" | "min-units" | "composite",
      children?: [...], noteJa? } ] }

courseMasters/{schoolDomain}/{faculty}/{courseId}             ← 코스별 自コース 과목 목록
  { nameJa, subjects: [{ name, allowedGrades, units }] }

users/{uid}: + faculty, admissionYear, courseId (2학년 선택 시)
users/{uid}/records/{recordId}                                ← 이수 이력 (성적표 기반 입력)
  { subjectName, code?, units, grade(S/A/B/C/F), year, zoneId(자동판정+수정가능) }
```
진행률 계산은 클라이언트: records를 zone별 집계 → requirementMaster와 대조.

### 검증·확정 사실
- **졸업요건 마스터**를 便覧 인쇄 p6과 대조해 확정(§1과 일치): 126 = 基礎8+외국어16+총합24+보건2+기본16+(연습·기간)48 최소치, 프리존 12.
- **자코스 28·기간영어 4·48 규칙** 확정(p21): 自コース28이상 + 基幹英語4이상 포함, 他コース과 합쳐 48이상.
- **7번째 코스 = クリエイティブ・ビジネス** 확정(p24·p28).

### 졸업 계산에 영향 주는 미묘한 규칙 (놓치면 오판정)
- **基幹英語科目은 고정 리스트가 아님**: 자·타코스 基幹科目 중 영어강의 과목을 **사전 신청**으로 인정. 연도 시라버스 의존.
  → **基幹英語로 인정된 단위는 自コース 28에 불산입.** 개인 이수기록에 "基幹英語 인정 여부" 플래그가 반드시 필요.
- **商学専門演習(3·4년)**: 담당교원이 自コース 소속이면 自コース科目, 아니면 他コース科目으로 산입 → 演習 담당교원 소속 데이터 필요.
- **유학생 특례**: 日本事情A~F 8단위까지 총합교육 산입 / 초습외국어 8단위를 「日本語」로 대체(둘 다 유학생만).
- **프리존 산입 상한**: 자격과정 8단위·타학부이수 20단위 등 상한이 있어 단순 합산 불가.
- 履修제한(연차별 이수단위 상한)은 별도 페이지 — 학기 계획 시뮬레이션에는 필요(이번 세션 미추출).

## 6. 아키텍처 가드레일 (2026-07-26 확정 · 재론 금지)

> 학점관리는 로드맵(7/8) 확정 후 얹은 기능이라 기존 구조와 마찰 소지가 있었음.
> 아래는 그 충돌·비효율을 미리 막기 위한 결정. **구현은 여전히 Phase 3(런칭 후).**
> 지금 필요한 건 코드가 아니라 "Phase 2가 학점관리를 망치지 않게 하는 경계선".

### 6-1. 학점관리 = 독립 서브시스템 (크롤러와 잇지 않는다)
- 졸업요건 판정의 **본선 루프는 `便覧(요건·과목→영역 마스터) × 성적표(개인 이수 이력)`로 자기완결**한다.
  진짜 조인은 "과목 → 영역(zone) 분류" 하나뿐이고, 그 권위 원본은 便覧 배당표(과목명→群).
- **크롤러(`schools/.../courses`)와는 잇지 않는다.** 이유:
  - **시점 불일치**: 성적표=과거 이수, 크롤러=현재 개설분. 몇 년 전 이수 과목은 올해 크롤에
    없을 수 있어(폐강·명칭변경·연도차) **원천적으로 크롤러로 분류 불가.** 성적표는 便覧으로만 분류.
  - 따라서 `courses ↔ courseMaster` 조인 키를 지금 확정할 필요 없음(철회). `Course`에 zone
    힌트 필드를 미리 예약할 필요도 없음(Firestore 스키마리스 → 나중에 옵셔널 필드 추가는 공짜).
- 크롤러가 학점관리에 닿는 **유일 지점** = "현재 시간표 과목을 이수 예정으로 미리 집계"(§3 v1-3).
  이는 미래지향 편의 기능(v2급 후순위)이고, 그때도 "잇는" 게 아니라 시간표 과목을 便覧으로 분류하면 됨.
- **Phase 2 영향**: 학점관리 때문에 **지금 courses·리뷰·시간표 스키마를 바꾸지 말 것.** 건드릴 이유 없음.

### 6-2. 저장·프라이버시 = 클라이언트 종단 암호화(E2E) 금고
요구: **학생이 보는 모든 값(진행률·GPA·과목별 성적)은 계정(uid)을 따라 기기가 바뀌어도 동일하게 보인다.**
동시에 성적은 운영자·유출·수사요청으로부터 보호. 두 요구를 함께 푸는 유일 해법이 E2E.

- **전 기록(이수기록·성적 letter·GPA)을 기기에서 암호화 → 암호문만 `users/{uid}/creditVault`에 저장.**
  서버는 평문 성적을 절대 보유하지 않음. **usersPublic 미러 금지**(GPA·진행상태 어떤 형태로도 공개 안 됨).
- 키 구조: 랜덤 DEK로 기록 암호화 → DEK를 **복구 암호**에서 파생한 키(Argon2id)로 wrap → wrapped DEK 동봉.
  기기 교체 시: 이메일 로그인으로 uid 복원 → 복구 암호 입력 → DEK 복호 → 동일 화면 재현.
- **감수하는 대가(암호학적 사실)**: 기기를 넘으며 "서버는 못 읽고 본인은 읽는"을 동시에 만족하려면
  서버가 모르는 사용자 비밀이 반드시 하나 필요 → **복구 암호 1회 설정**(로그인 비번과 별개).
  **분실 시 금고 복구 불가.** 보조 안전망으로 **암호화 백업 파일 export** 제공.
- 이 방식이 §5의 "성적 기기 밖 미전송" 원칙을 충족(서버엔 암호문뿐) + "이메일=데이터 인계 열쇠"와 정합.
- **파생 결정**: 서버가 못 읽으니 필드 단위 분리(성적만 로컬 등)는 불필요 → 통째 암호화·통째 동기화.

### 6-3. Phase 2가 반드시 의식할 접점 (블로커 아님, 인지 사항)
- **입학년도(admissionYear) ↔ Phase 2 "학년 필터" 단일 소스화.** 11월 2주차 "선배 시간표 열람"에
  학년 필터가 들어가는데, 학점관리 마스터는 `admissionYear`를 키로 씀. **둘을 따로 저장하면 충돌·재작업.**
  원칙: **입학년도(불변)를 단일 소스로 저장하고 학년은 파생**(현재연도−입학년도). Phase 2에서 학년 개념을
  넣을 때 mutable한 "학년" 필드를 새로 만들지 말 것. → `users/{uid}`의 `admissionYear` 하나로 통일.

### 6-4. 선행 의존 (착수 금지 조건)
- **schoolDomain "global" 부채 해소가 선행 조건.** 학점관리는 본질적으로 `(학교×학부×입학년도)` 스코프라,
  `AuthContext`가 실교 school/faculty/입학년도를 깨끗이 제공하기 전엔 착수 불가. 이 부채는 게시판(준희 축)
  포함이라 **준희 복귀 후 조율**. → ROADMAP §6 기술부채 참조. **(2026-07-27 부채 해소 완료 → 선행조건 충족)**
- **마스터 전체 스키마 확정·로드맵 일정 편입은 위 부채 해소 이후로 미룸.** 표본이 상학부 2026 한 벌뿐이라
  조기 확정은 과설계 위험.

## 7. 「시간표 마술사」 = 메인기능 승격 검토 (2026-08-31)

> 사용자 요청: 졸업요건 추적을 **앱 메인 기능**으로. "시간표를 짤 때 지금 담긴 과목이면 졸업/진급 요건을
> 각각 얼마나 채웠는지"를 실시간으로 보여주는 **시간표 마술사**. 첨부로 본인 성적표 재제출.

### 7-1. 성적표 재확인 (학번 1210210127 = §4 그 샘플 본인)
- 商学部 商学科 **グローバル・ビジネスコース** / 2021년 입학 / 현재 **3년** / GPA 2.46 / GP총계 310.
- **취득 합계 118** / 졸업요건 총계 ≈ **134~136**(성적표 표기 134 · 사용자 기억 136 — **2021 便覧으로 확정 필요**).
- 성적표의 **単位修得状況** 표가 이미 (영역 × 必要 × 취득 × 合計) 구조 → **우리가 만들 대시보드의 완성형 원형**.
  또한 이수 과목이 이미 영역별(基礎/総合/外国語/基本/基幹 自·他コース/演習/その他/他学部…)로 그룹됨
  → **개인 이수기록의 "과목→영역" 분류 정답지가 성적표 안에 내장.** 手입력 UX = "성적표 보며 그대로".

### 7-2. 마술사 런타임 설계 (결정론, LLM 0)
```
zoneState(zoneId) = {
  required,                         // 便覧 마스터
  acquired = Σ(records where zone==zoneId, grade≠F).units,   // 성적표 이력(금고)
  planned  = Σ(현재 편집중 시간표 과목 where zone==zoneId).units, // 미래 학기(미확정)
  projected = acquired + planned,
  status = projected>=required ? "충족" : "부족",
}
```
- **핵심 인터랙션**: 시간표에 과목을 담을 때 그 과목의 zone을 판정해 **델타를 즉시 표시**
  ("この講義 → 基幹科目·自コース +2 (26→28 ✅달성)"). 빼면 반대로 감산.
- 화면: 시간표 아래/옆에 **zone별 진행 게이지(퀘스트 카드)**. 색=충족/부족/초과. 상단에 "졸업까지 남은 단위·미충족 영역 N개" 요약.
- **분류의 권위 원본 = 便覧 배당표(과목명→群)**. 크롤러 courses와는 잇지 않음(§6-1). 시간표 과목도 便覧으로 분류.

### 7-3. 놓치면 오판정 (§5 규칙을 마술사에 반영)
- `基幹英語` 인정 플래그(自コース28 불산입) · `商学専門演習` 담당교원 소속(自/他) · 유학생 특례(日本事情8·日本語대체)
  · 프리존 상한(자격8·타학부20 등) · **연차별 履修제한 상한**(시간표 "짜기" 시뮬레이션엔 필수 — 미추출, §5).
- → 마스터 스키마에 `rule: all-required | min-units | composite | freezone-cap`, 기록에 `kikanEnglish:bool`·`seminarAffiliation` 필드.

### 7-4. 메인기능 승격에 대한 권고 (정직한 평가)
- **최고의 차별화 기능이자 최고 난이도·최고 리스크.** 오판정=졸업 오안내=신뢰 붕괴. 데이터 정확도가 생명.
- **권고: 1.0(1월 제출)엔 넣지 않음.** 3중 부담(입학년도×학부별 마스터 제작 병목 / E2E 금고 구현 / 정확도 검수).
  대신 **런칭 후 성장기의 헤드라인 기능**으로. "메인"으로 밀려면 → **범위 좁힌 MVP**:
  상학부 × 소수 입학년도(2021~2026)부터, 手입력+게이지 먼저, 시뮬레이션(履修제한 경고) 다음.
  **포지셔닝은 "졸업 보증"이 아니라 "참고·셀프체크"**(오판정 리스크 완충 + 면책).
- 확장 열쇠는 자동화가 아니라 **재사용**: 마스터는 `(학부×입학년도)` 단위라 소수·거의 불변 → 트랙A(便覧→LLM초안→검수→verified) 1회 제작으로 그 코호트 전원 커버.

### 7-5. 便覧 p39~40 스크린샷 확인 (2026-08-31)
- **p39 = 「卒業要件について(2023년도 以降 입학자)」 = 126単位.** CREDIT-TRACKING §1(2026)과 동일 → **2023~2026 코호트는 126 마스터 1벌로 커버**.
  注意事項 ①~⑥이 §5 까다로운 규칙과 정확히 일치(자코스28·基幹英語4·48 / 演習 담당교원 소속 / 유학생 日本事情8 / 프리존12 / **4년차 최저 12단위**).
- **p40 = 授業科目及び担当者一覧표 = "과목→区分(영역)" 권위 배당표.** 형식: `区分 / 配当年次 / 授業科目 / 単位数 / 担当者`.
  「開講せず」·「メディア授業는 60単위까지 산입」 등 부가규칙 포함. 이 표를 그대로 파싱하면 마스터의 과목→zone 사전이 나옴.
- **⚠️ 사용자(2021 입학)는 "2022년도 以前 입학자" → 요건이 다름.** p39가 "2022년도 이전은 **P58** 참조"라고 명시.
  즉 **본인 마스터는 이 便覧의 P58(요건표) + 商学部 배당표**에서 나옴(전 182p 불필요).

### 7-7. 면책 디스클레이머 (2026-08-31 방향 확정, 사용자 발의)

  - KO: "표시되는 값은 참고용 추정입니다. 실제 단위 수와 졸업·진급 가능 여부는 반드시 대학 공식 정보(Oh-o! Meiji·履修要項)에서 직접 확인하세요."

### 7-9. 제안 엔진 설계 — "뭘 더 넣어야 / 넣을 수 있나" (2026-08-31, 방향 확정)
> 사용자가 가장 가치 있다고 짚은 부분. 마술사의 두뇌. **기존 기능을 전부 묶는 캡스톤**.

**입력**: master(zone별 required·rule) · records(zone별 취득) · timetable(예정) · constraints(배당년차·이수상한·미디어상한·개설학기) · courses(개설과목) · reviews(강의평) · friendOverlap.

**출력 = 2개 리스트:**
1. **MUST(채워야) — 부족한 필수/최소 요건.** zone별 `projected < required`의 부족분. 우선순위:
   `진급 블로커(2→3년 42단위 미충족) > 졸업 필수 부족(自コース28·基幹英語4 등) > 영역 최소 부족 > 프리존 부족`.
   배당년차 마감 임박(예: 남은 게 3·4년 배당뿐인데 4학년) 가중.
2. **CAN(넣을 수 있는) — 여유·자유선택.** 필수는 찼고 이수상한 여유 내에서 담을 수 있는 것(프리존·관심분야). 강의평 평점 우선.

**하드 필터(절대 추천 안 함)**: 현재 학년이 배당년차에 없음 / 이미 합격 이수 / 이번 학기 미개설 / 담으면 이수상한(학기 22 등) 초과 / 미디어 60 초과 / 시간대 충돌.

**소프트 신호(정렬 가중)**: 강의평 평점(기존 reviews) · 친구 겹침(기존 friendOverlap) · 재수강 필요(F 이력).

**전략 펀치라인 — 이 엔진이 기존 기능을 전부 복리로 묶는다:**
- 부족분 판정 = 便覧 마스터 × 성적표(§7-2)
- 후보 과목 = **강의검색**(courses)
- 정렬 = **강의평**(별점) + **친구 겹침** + 시간대 충돌 회피(**시간표** 로직)
- 결과 = 원탭으로 **시간표**에 반영 → 게이지 즉시 갱신
→ 즉 마술사는 신규 데이터가 아니라 **이미 있는 것들의 오케스트레이션**. "이 수업 들으면 졸업에 도움 되나?"에 즉답.

**준희님(2021·G·B·3년) 실제 제안 결론**: 必修·教養·基本 전부 충족. **남은 ≈16단위 = 基幹科目(自コース 28↑ 이미 충족 → 他コース/演習으로 48 채우기) 약 10 + 프리존 약 6.** 3·4년 배당 基幹 위주, 秋 22단위 상한 내. 진급조건은 이미 충족(3년), 단 4학년 최저 12단위 규정 유의.
